# Execution Log Policy

执行任何实际任务后，必须补充一份执行日志，作为交付的一部分。

## 强制要求

1. 日志目录固定为 `./ExecuteLogs`。
2. 如果目录不存在，先创建目录再写日志。
3. 每次任务完成后新增一份日志，不覆盖历史日志。
4. 文件名格式为 `YYYY-MM-DD_任务名总结.md`。
5. `任务名` 使用简短中文概括，避免过长，能够直接看出本次任务主题。

## 日志内容模板

日志至少包含以下两部分：

### 计划清单

使用 markdown checklist 记录执行计划，例如：

```md
## 计划清单
- [x] 理解需求
- [x] 修改相关文件
- [x] 补充必要配置
- [x] 整理交付结果
```

### 最终完成

清楚列出最终完成的事项，例如：

```md
## 最终完成
- 新增 xxx
- 调整 xxx
- 产出本次执行日志
```

## 执行约束

- 日志内容默认使用中文。
- 日志应反映本次真实执行过程，不写与本次任务无关的内容。
- 只有在任务真正完成或明确交付当前阶段结果时，才写入日志。
- 如果任务范围发生变化，日志中的“计划清单”应以最终实际执行内容为准。
